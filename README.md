# PuppyRuby · 너와 나의 작은 행복

## 배포와 로컬 실행

운영 구성은 **Vercel의 Next.js 프런트엔드 + AWS의 Java 21 백엔드 + 영구 PostgreSQL**입니다. Docker 없이 배포합니다. Vercel은 Root Directory를 `frontend`, Framework Preset을 `Next.js`, Build Command를 `npm run build`로 지정하고 Output Directory는 프레임워크 기본값을 사용합니다. `.next/standalone`을 출력 디렉터리로 지정하지 않습니다.

로컬 개발은 화면 **3000**, Java API **8080** 포트를 사용합니다. 운영 사이트는 `https://실제-사이트-도메인`으로 접속하며 주소에 `:3000`을 붙이지 않습니다. Vercel의 `API_URL`에는 `https://실제-백엔드-도메인/api/v1`, 양쪽의 `PUBLIC_SITE_URL`에는 실제 사이트 HTTPS 주소를 입력합니다. AWS JAR 실행·DB 설정·빌드 오류 복구는 [배포 안내](docs/DEPLOYMENT.md)를 참고하세요.

## 화면 모드와 산책 시간

화면 상단의 해·달 버튼으로 라이트/다크 모드를 바꿉니다. 흰색·검은색 중심의 글자와 버튼을 사용하며 다크 모드에는 별 배경이 나타납니다. 선택은 브라우저에 저장하고 다른 탭에도 반영합니다. 처음 방문하면 기기의 화면 모드 설정을 따릅니다.

산책 풍경은 화면 모드와 별도로 **한국 시간(Asia/Seoul)**에 따라 자동으로 바뀝니다. 낮은 **06:00–17:00**, 노을은 **17:00–20:00**, 밤은 **20:00–다음 날 06:00**입니다. 산책 로비와 방 안의 풍경이 같은 시간을 따르며, 켜 둔 화면도 전환 시각과 탭 복귀 시 갱신됩니다. 별 반짝임은 기기의 동작 줄이기 설정을 존중합니다.

## 이메일·카카오 회원과 관리자

상단 **로그인 / 회원가입**에서 계정을 만들고 `/account/me`에서 집사 이름, 비밀번호, 이메일 인증, 내 강아지와 PC 연결을 관리합니다. 처음 가입할 때 지금 키우는 강아지를 계정에 저장합니다. `/admin`은 서버가 권한을 확인하는 관리자 화면으로 회원 조회·정지/해제, 산책방 폐쇄와 메시지 숨김을 제공합니다.

이메일 가입·로그인은 바로 사용할 수 있으며 카카오 로그인과 인증·재설정 메일에는 외부 서비스 설정이 필요합니다. `ADMIN_EMAIL`에 지정한 이메일을 인증하면 관리자가 됩니다. 설정과 사용법은 [회원 기능 안내](docs/ACCOUNTS.md)에 있습니다. 로컬 서버는 `backend/start-server.ps1`로 시작하면 `backend/.env.local` 설정과 기존 데이터를 사용합니다.

## 관리자가 고르는 16가지 도트 스타일

`/admin`의 **도트 스타일**에서 같은 견종으로 16가지 그림체를 비교합니다. 클래식·동글 얼굴·찹쌀떡·왕머리·콩알·인형·동화·만화·레트로·미니·스티커·구름·복슬복슬·주머니·쿠키·얼굴 배지 중에서 선택할 수 있습니다.

[16가지 스타일 한눈에 보기](docs/previews/dog-styles-16.png)

각 카드의 **삭제**로 원하지 않는 스타일을 목록에서 제외하고 **변경사항 저장**을 누릅니다. 삭제한 스타일은 전체 기본·견종별 선택 메뉴에서도 제외됩니다. 사용 중인 기본 스타일을 삭제하면 남은 첫 스타일로 전환하고, 삭제한 개별 지정은 새 기본 스타일을 사용합니다. 최소 한 스타일은 남겨야 합니다. **삭제한 스타일** 목록에서 복원한 뒤 저장할 수 있으며 **변경 되돌리기**로 저장 전 편집을 취소할 수 있습니다.

**전체 적용**은 모든 견종의 기본 스타일을 정하고 개별 설정을 해제합니다. **견종별 적용**은 선택한 견종만 바꾸며, 각 견종을 다시 기본 스타일 상속으로 돌릴 수도 있습니다. 선택과 비교는 미리보기이고, **저장**해야 실제 사이트에 반영됩니다. 최초 설정은 기존 클래식 스타일입니다. 포메라니안·토이 푸들·말티즈·시바견·웰시 코기·비글과 소개 화면의 사모예드까지 설정할 수 있습니다.

설정은 서버 DB에 보관하며 소개·우리 집·옷장·도감·산책의 공통 강아지 그림에 적용됩니다. 저장한 탭은 즉시, 다른 탭은 저장 알림이나 화면 복귀 시, 다른 방문자의 열린 화면은 최대 약 30초 뒤 갱신됩니다. 강아지의 털색·눈 색·액세서리·이름·성장 데이터는 유지됩니다. 이 설정은 웹 그림체 설정이며 기존 Windows 실행파일에 내장된 도트는 바꾸지 않습니다.

관리자 인증·권한 확인, 변경 이력 기록, 동시 저장 충돌 감지를 적용합니다. 검증: `scripts/verify-appearance.mjs`는 3101 포트의 별도 프런트와 폐기 가능한 DB·로컬 메일함에서만 실행합니다.

## Windows 실행형 강아지

**`desktop/dist/PuppyRuby.exe`**를 실행하면 다른 프로그램 위에서 마우스 이동·클릭·키보드·스크롤에 반응하는 픽셀 강아지가 나타납니다. 사이트 첫 화면의 **Windows용 강아지 받기**로도 다운로드할 수 있습니다. 단독 모드는 서버 없이 실행되며 키보드 입력 내용은 읽거나 저장하지 않습니다.

0.5에서는 강아지가 커서 옆으로 부드럽게 걸어옵니다. 우클릭 **마우스 따라가기 / 여기에 멈추기**로 이동을 바꾸고, 드래그해 놓은 자리에도 머뭅니다. 평소에는 강아지 그림만 보이며 말풍선은 답변할 때 잠깐 나타납니다. 우클릭 또는 트레이에서 견종·크기·입력 반응·종료를 설정합니다. 자세한 사용법과 빌드: [desktop/README.md](desktop/README.md).

웹 정원에도 페이지 내 마우스 시선·클릭·키보드·빠른 타이핑·휠·드래그 반응을 추가했습니다. 페이지 바깥 입력은 Windows 실행파일에서만 감지합니다.

## 성장하며 배우는 명령과 단축키

우리 집의 **루비에게 물어봐** 또는 실행파일 **우클릭 → 강아지에게 물어보기**에서 `엑셀 붙여넣기 단축키 알려줘`라고 물으면 **“Ctrl + V다 멍!”** 하고 답합니다. Windows용 엑셀·한글 단축키를 Microsoft·한컴 공식 도움말로 확인한 공통 사전 `shared/commands.json`으로 제공합니다.

| 등급 | 누적 명령 | 새로 배우는 내용 |
|---|---:|---|
| N | 1 | 앉아 |
| R | 8 | 손, 엑셀 기본 단축키 6개 |
| SR | 19 | 기다려, 엑셀 작업 단축키 4개, 한글 기본 단축키 6개 |
| SSR | 28 | 돌아·빵, 엑셀 고급 단축키 2개, 한글 고급 단축키 5개 |

잠긴 명령은 필요한 등급을 안내하고, 승급하면 새 명령이 즉시 열립니다. 질문은 경험치·하트·에너지를 바꾸지 않습니다. 웹과 연결한 실행파일은 웹의 돌봄·훈련 규칙을 함께 사용합니다. 연결하지 않은 단독 모드에서는 간식·성공한 훈련으로 10초마다 +10 XP를 모아 100 XP로 승급하며 PC에 따로 저장합니다.

## 웹 강아지와 실행파일 연결

1. `/play#home`의 **실행파일과 연결**에서 새 실행파일(0.4 이상)을 다운로드합니다.
2. **연결 코드 만들기**를 눌러 5분 동안 유효한 일회용 코드를 발급합니다.
3. 실행파일의 강아지를 우클릭하고 **웹 강아지와 연결**에서 사이트 주소와 코드를 입력합니다.

웹에서 선택한 강아지의 이름·견종·털색·눈동자·액세서리·등급·경험치를 PC에서도 불러옵니다. 연결 중의 돌봄·훈련·승급은 같은 서버에 저장되며 약 5초 안에 양쪽에 반영됩니다. 웹에서 다른 강아지를 선택하면 PC도 따라 바뀝니다. 최대 5대까지 연결하고 웹에서 개별 연결을 해제할 수 있습니다. 연결 구조와 검증은 [웹·PC 연결 안내](docs/DESKTOP_SYNC.md)를 참고하세요.

인터넷이나 서버 연결이 끊기면 마지막 강아지를 표시하며 보상을 주는 행동은 재연결 후 계속합니다. 연결 전 PC 강아지는 보존하고 연결 해제 시 다시 사용합니다. 기존 성장 정보를 합산하지 않습니다. 연결 정보는 Windows 사용자별 암호화 저장소에 저장하며 실행파일에는 게임 정보만 전달합니다. 산책 친구의 이름·사진·채팅은 전달하지 않습니다. 현재 로컬 사이트에 연결하려면 이 프로젝트의 프론트엔드와 백엔드가 실행 중이어야 합니다.

## 픽셀 강아지 사이트

산책 프로필의 사진 등록은 **프리사인드 URL로 S3에 직접 업로드 → 서버 확인 → CDN 표시** 흐름을 사용합니다. 로그인한 회원만 새 사진을 올릴 수 있으며 기존 사진은 유지합니다. Java 서버 환경변수에 S3 버킷·리전·CDN 주소를 등록한 뒤 `S3_UPLOAD_ENABLED=true`로 켭니다. Vercel에는 외부 Java 서버를 가리키는 `API_URL`을 설정합니다. 변수 목록, S3 CORS와 권한 설정은 [이미지 업로드 연결 안내](docs/IMAGE_UPLOADS.md)에 있습니다.

**함께 산책하기**: `/play#walk`에서 산책방을 만들거나 입장하고, 돌아다니는 강아지들 아래 채팅창에서 이야기합니다. `쿠키엄마 (28)`처럼 별명·나이를 표시하며, 친구 요청을 서로 수락하면 등록한 이름과 사진을 공개합니다. 사용법과 저장 규칙은 [산책방 안내](docs/WALK.md)를 참고하세요.

- `/`: 콤냥이의 캐릭터 중심 소개 구성을 참고한 퍼피루비 랜딩 페이지. 픽셀 정원, 견종 선택, 쓰다듬기·간식·공놀이·낮잠, 낮/밤 전환, 확대 보기, 털색 미리보기, 25분 집중 타이머, 이용 안내를 제공합니다. 서버 없이도 첫 화면 체험이 가능합니다.
- `/play`: 기존 분양·돌봄·훈련·옷장·도감. 강아지와 정원을 픽셀 스타일로 변경했습니다. `/play#closet`으로 옷장에 바로 들어갈 수 있습니다.
- 정원의 견종·털색 선택은 미리보기이며 게임 소유 데이터에 적용되지 않습니다. 실제 꾸미기는 우리 집 옷장에서 저장합니다.
- 캐릭터는 제공된 퍼피루비 견종 참고 자료를 바탕으로 작성한 SVG 픽셀 아트입니다. 한글 픽셀 글꼴은 Galmuri(SIL OFL)를 패키지로 포함합니다.
- PC 및 390px 모바일 화면에서 확인했으며, 320px에서도 가로 넘침을 점검했습니다. 타입 검사와 프로덕션 빌드, 꾸미기 저장 후 새로고침 유지까지 검증했습니다.

기존 `frontend/.env.local`과 `backend/.env.local`을 사용한다면 `API_URL`, `PORT`, `PUBLIC_SITE_URL`이 현재 실행 주소와 일치하는지 확인하세요. 기본 포트를 다른 프로그램이 사용 중이면 그 프로그램을 종료할 필요 없이 별도 로컬 포트를 사용할 수 있습니다. 기존 미리보기의 포트도 그대로 유지할 수 있으며, 로컬 설정 파일은 예제 파일을 수정해도 자동으로 바뀌지 않습니다.

강아지를 분양받고, 돌보고, 꾸미며 위로받는 웹 서비스의 실행 가능한 개발 토대입니다.
같은 위치의 `hwaryeok`를 참고해 **Next.js 프론트엔드 / Spring Boot 백엔드**로 분리했습니다.
기존 화력의 코드·데이터·환경 비밀값은 복사하지 않았습니다. 호환 버전과 공개 Gradle Wrapper만 재사용했습니다.

## 프로젝트 구조

```text
PuppyRuby/
├─ frontend/                   Next.js 16.3.4 · React 19.2.8 · TypeScript · Tailwind 4
│  ├─ src/app/                 페이지, 레이아웃, 공통 스타일
│  │  └─ api/game/             Next.js → Spring Boot 프록시, HttpOnly 방문 쿠키
│  ├─ src/components/          우리 집·분양·옷장·도감, 강아지 렌더링
│  ├─ src/lib/                 API 타입, 견종·꾸미기 카탈로그
│  └─ public/images/           여섯 견종 스프라이트, 거실 배경
├─ backend/                    Spring Boot 4.1 · Java 21 · Gradle 8.14.3
│  ├─ src/main/java/com/puppyruby/
│  │  ├─ game/                 도메인, JPA 저장소, 게임 서비스, REST 컨트롤러
│  │  └─ config/               API 예외 응답
│  ├─ src/main/resources/      H2 / PostgreSQL 연결 설정
│  └─ src/test/                게임 규칙, 중복 요청·동시성 검증
├─ docs/                       서비스 기획, API 명세, 이미지 제작 기록
└─ docker-compose.yml          기존 선택형 로컬 구성 (운영 배포에는 사용하지 않음)
```

## 바로 실행

Node.js 24와 Java 21이 필요합니다. 각각 별도 터미널에서 실행하세요.

```powershell
# 터미널 1: 서버 (처음 실행 시 Gradle 의존성을 내려받습니다)
cd backend
.\gradlew.bat bootRun

# 터미널 2: 화면
cd frontend
npm install
npm run dev
```

- 화면: **http://127.0.0.1:3000**
- API: http://127.0.0.1:8080/api/v1/game
- 상태 확인: http://127.0.0.1:8080/actuator/health
- 기본 H2 파일 DB는 `backend/data/`에 저장됩니다. 서버를 껐다 켜도 데이터가 남습니다.
- `frontend/.env.example`을 `.env.local`로 복사하면 API 주소를 바꿀 수 있습니다.
- `backend/.env.example`은 환경 변수 안내용입니다. Spring Boot가 `.env`를 자동으로 읽지는 않습니다. `backend/start-server.ps1`로 `.env.local`을 읽거나 해당 프로세스의 환경 변수로 전달하세요.

## 구현된 흐름

- 루비(R 등급)와 하트 1,000개로 시작합니다.
- 새 가족은 강아지 뽑기권 1매로 만납니다. 가격과 견종·등급별 확률은 관리자에서 설정하며 상점에 공개됩니다. 기존 하트 분양 API는 차단됩니다.
- 모든 견종에 모든 등급이 존재하며, 경험치 100을 써서 한 단계씩 SSR까지 성장합니다.
- 명령 성공률: N 45%, R 65%, SR 80%, SSR 95%. 서버의 난수로 판정합니다.
- 밥 주기·놀아 주기·쉬게 하기, 등급별 앉아·손·기다려·돌아·빵 훈련, 엑셀·한글 단축키 질문, 이름 바꾸기.
- 털색 5종, 눈동자 4종, 액세서리 3종과 장착 해제. 미리보기 후 저장합니다.
- 새 가족 결과창, 가족 선택, 전체 견종 도감, 등급 필터, 반응형 화면.
- 오늘의 선물은 한국 시간 기준 하루 1회 하트 150개입니다.
- 모든 게임 상태는 서버 DB에 저장됩니다. 하트·훈련·등급·중복 보상 검증도 서버가 처리합니다.

## 운영 DB와 AWS Java 서버

AWS에서는 빌드한 `backend/build/libs/puppyruby-api-0.2.0.jar`를 Java 21로 실행합니다. `PORT=8080`과 영구 PostgreSQL의 `DB_URL`, `DB_USERNAME`, `DB_PASSWORD`를 서버 환경에 지정합니다. ALB가 다른 호스트에서 연결하는 구성은 `SERVER_ADDRESS=0.0.0.0`을 사용하고 보안 그룹에서 연결 경로를 제한합니다. HTTPS는 ALB 또는 리버스 프록시에서 처리합니다.

[배포 안내](docs/DEPLOYMENT.md)에 Vercel 설정표, AWS systemd 예시와 재배포 절차가 있습니다. 저장소의 Docker 파일은 기존 로컬 구성 자료이며 이 운영 배포에는 필요하지 않습니다. 실제 AWS·Vercel 배포 및 운영 PostgreSQL 연결은 별도로 확인해야 합니다.

## 토대의 범위

가입 전에는 브라우저 방문자 기반 체험을 제공합니다. 회원가입하면 체험 데이터를 계정에 귀속하고, 다른 브라우저에서도 이메일·카카오 로그인으로 이어갑니다. 가입하지 않은 체험은 쿠키를 지우면 새로 시작합니다. 실행파일은 일회용 코드로 현재 선택한 강아지에 연결합니다.

회원 인증·비밀번호 재설정·권한 검사·인증 시도 제한을 구현했습니다. 공개 운영에는 실제 카카오/메일 설정과 운영 DB 마이그레이션(Flyway), 백업 구성이 필요합니다. 기본 API는 로컬 루프백에 바인딩하며 AWS에서는 접속 구조에 맞춰 서버 주소를 지정합니다. 현재 `ddl-auto: update`는 개발 토대용입니다.
뽑기권과 결제 연동은 아래 안내와 같이 구현되어 있습니다. 아이템 교환·다중 치장품 동시 장착·동작별 애니메이션 스프라이트는 아직 구현하지 않았습니다. 캐릭터는 SVG 도트와 눈동자·장식 레이어를 합성하며, 명령 반응은 간단한 동작 효과입니다.

세부 규칙: [서비스 기획](docs/SERVICE_PLAN.md) · [API](docs/API.md) · [이미지 제작 기록](docs/ASSETS.md)


## 뽑기 상점 · 토스페이먼츠

- `/shop` 또는 `/play#adopt`: 강아지·아우라(윤곽선)·치장품 뽑기권, 전체 획득 확률, 보관함 착용, 뽑기·구매 내역.
- `/admin` → **뽑기·상품**: 1매/10매 상품 6종의 가격·판매 여부, 3개 풀의 항목별 가중치를 수정하고 저장합니다. 초기 전체 판매는 꺼져 있습니다.
- 기본 콘텐츠: 강아지 6견종 × 4등급, 아우라 8종, 치장품 7종. 강아지는 중복도 새 가족, 장식 중복은 보유 수량으로 쌓입니다. 공개 확률은 실제 서버 추첨에 사용하는 가중치에서 계산됩니다.
- 결제 승인 검증 후 해당 계정에 뽑기권을 한 번만 지급합니다. 뽑기 재시도도 같은 요청 번호에는 한 번만 차감·지급합니다. 토스 API로 확인한 취소·부분 환불은 잔액에 반영하며, 이미 사용하여 음수가 되면 뽑기가 일시 제한됩니다.
- 결제 키가 없으면 구매 버튼은 비활성화됩니다. 테스트와 실제 판매 설정, 웹훅 등록 및 운영 확인은 [결제 연동 안내](docs/PAYMENTS.md)를 참고하세요. 키는 브라우저 코드나 채팅에 넣지 않습니다.
- 아우라·치장품 착용 정보는 집·도감·산책 및 PC 동기화 데이터에 포함됩니다. 이미 배포된 기존 EXE는 새 장식 렌더러를 포함하지 않으므로 새 아우라·치장 표시에는 별도의 PC 앱 업데이트가 필요합니다.
