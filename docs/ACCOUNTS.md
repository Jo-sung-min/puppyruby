# 회원·마이페이지·관리자

## 화면

| 주소 | 기능 |
|---|---|
| `/account` | 이메일 로그인, 회원가입, 카카오 로그인 |
| `/account?mode=signup` | 이메일 회원가입 |
| `/account/me` | 집사 이름 수정, 이메일 인증, 비밀번호 변경, 내 강아지·돌봄 요약, PC 연결, 로그아웃 |
| `/account/reset` | 비밀번호 재설정 메일 요청 |
| `/account/verify?token=…` | 받은 인증 링크 확인 |
| `/admin` | 관리자 통계, 회원 검색·이용 정지/해제, 산책방 폐쇄, 메시지 숨김 |

가입 전에는 기존 브라우저 체험을 사용할 수 있습니다. 처음 가입할 때 해당 브라우저의 강아지·옷장·하트·산책 프로필·기존 PC 연결을 계정에 귀속합니다. 이미 가입한 계정으로 로그인하면 그 계정의 데이터를 불러오고 다른 체험 데이터와 자동으로 합치지 않습니다. 가입에 사용한 옛 방문 쿠키만으로는 회원의 강아지에 접근할 수 없습니다.

## 로컬 서버 실행과 설정

Java 21과 Node.js가 필요합니다. 아래 명령은 서버를 `backend` 작업 폴더에서 실행하여 기존 `backend/data` 데이터를 계속 사용합니다.

```powershell
.\backend\start-server.ps1
```

이 스크립트는 무시되는 `backend/.env.local`을 읽습니다. 처음 설치하는 환경에서는 `backend/.env.example`을 복사한 뒤 값을 입력하세요. 현재 프로젝트의 로컬 서버는 `PORT=8082`, 웹은 3001입니다. 이미 실행 중인 서버를 먼저 종료한 뒤 시작합니다. 화면 서버는 별도 터미널의 `frontend`에서 `npm run dev`로 실행합니다.

Spring Boot를 `java -jar` 또는 `bootRun`으로 직접 시작하면 `.env.local`은 자동으로 읽지 않습니다. 이 경우 동일한 환경 변수를 해당 프로세스에 전달해야 합니다. 설정 파일은 코드처럼 실행하지 않고 허용된 이름과 문자열 값만 읽습니다.

| 설정 | 위치 | 용도 |
|---|---|---|
| `PUBLIC_SITE_URL` | 백엔드·프론트 | 실제 사이트 기본 주소. 로컬은 `http://127.0.0.1:3001`, 공개 사이트는 HTTPS |
| `ADMIN_EMAIL` | 백엔드 | 관리자로 지정할 이메일. 해당 이메일을 인증한 계정만 관리자 승격 |
| `KAKAO_REST_API_KEY` | 백엔드·프론트 | 카카오 앱 REST API 키 |
| `KAKAO_CLIENT_SECRET` | 백엔드 | 카카오 앱 클라이언트 시크릿 |
| `MAIL_ENABLED` | 백엔드 | 실제 메일 발송 사용 여부, 기본 `false` |
| `MAIL_HOST`, `MAIL_PORT` | 백엔드 | SMTP 서버와 포트, 기본 포트 587 |
| `MAIL_USERNAME`, `MAIL_PASSWORD` | 백엔드 | SMTP 인증 정보 |
| `MAIL_FROM` | 백엔드 | 발신이 허용된 이메일 주소 |
| `MAIL_STARTTLS` | 백엔드 | SMTP TLS 사용, 기본 `true` |

이메일 주소·비밀번호로 가입하고 로그인하는 기능은 SMTP 없이도 사용할 수 있습니다. 이메일 소유권 인증·비밀번호 재설정 메일과 관리자 자동 승격에는 실제 발송 설정이 필요합니다. 설정되지 않은 외부 서비스는 준비 중으로 표시하며 인증 성공을 만들어 내지 않습니다.

### Docker Compose 설정

Docker에서는 프로젝트 루트의 `.env.example`을 `.env`로 복사하고 `POSTGRES_PASSWORD`를 설정합니다. 같은 파일에 위 회원 설정을 입력한 뒤 프로젝트 루트에서 `docker compose up -d --build`로 시작합니다. Compose는 `backend/.env.local`이나 `frontend/.env.local`을 읽지 않습니다.

`PUBLIC_SITE_URL`에는 브라우저로 접속하는 기본 주소를 입력합니다. 로컬 기본값은 `http://127.0.0.1:3001`이며, 공개 서비스는 HTTPS 주소를 사용합니다. 이 값은 두 컨테이너에 동일하게 전달되어 인증 메일 링크와 카카오 콜백 주소에 사용됩니다. `http://backend:8081` 같은 컨테이너 내부 주소를 넣지 않습니다.

처음에는 관리자 이메일·카카오 키·SMTP 인증 정보가 비어 있고 메일 발송은 꺼져 있습니다. `ADMIN_EMAIL`, 카카오 클라이언트 시크릿과 SMTP 설정은 백엔드에만 전달합니다. 프론트에는 사이트 주소와 카카오 REST API 키만 전달합니다. 설정을 바꾼 뒤에는 `docker compose up -d`로 컨테이너를 다시 생성하여 적용합니다. 실제 이메일·비밀번호·시크릿은 `.env`에만 입력하고 예제 파일에는 저장하지 않습니다.

## 카카오 설정

1. 카카오 개발자 앱에서 카카오 로그인을 활성화합니다.
2. Redirect URI에 `PUBLIC_SITE_URL/api/auth/kakao/callback`을 정확하게 등록합니다. 로컬은 `http://127.0.0.1:3001/api/auth/kakao/callback`입니다.
3. REST API 키와 클라이언트 시크릿을 환경 설정에 입력합니다. 프론트에는 REST API 키만 사용하며 시크릿은 백엔드에만 둡니다.
4. 닉네임·이메일 동의항목은 앱에서 허용된 범위로 설정합니다. 이메일 제공에 동의하지 않아도 카카오 고유 사용자 ID로 가입할 수 있습니다.

서버가 인가 코드를 카카오의 토큰 API와 사용자 정보 API로 교환합니다. 브라우저가 보낸 사용자 번호를 신뢰하지 않습니다. 로그인 시작 시 생성한 임의 `state`를 HttpOnly 쿠키와 대조하며 10분 후 만료됩니다. 카카오 이메일이 기존 이메일 회원과 같아도 계정을 자동으로 합치지 않습니다.

공식 문서: [카카오 로그인 REST API](https://developers.kakao.com/docs/ko/kakaologin/rest-api)

## 관리자 지정

`ADMIN_EMAIL`에 지정한 주소로 가입하고 마이페이지에서 이메일 인증을 완료하세요. 인증 후 관리자 메뉴가 표시됩니다. 이미 인증한 계정은 다시 로그인하면 설정을 적용합니다. 처음 가입했다는 이유만으로 관리자가 되지 않으며, 클라이언트가 보낸 `role` 값도 사용하지 않습니다.

회원 정지는 기존 웹 세션, PC 연결 토큰과 미사용 연결 코드를 폐기합니다. 해제해도 이전 세션이 살아나지 않으며 다시 로그인·연결해야 합니다. 본인이나 다른 관리자는 정지할 수 없습니다. 방 폐쇄 시 참여자는 로비로 돌아가고 다시 입장할 수 없습니다. 숨긴 메시지는 일반 산책 화면에서 제외합니다. 조작한 관리자·대상·사유·시각을 감사 기록으로 남깁니다.

## 인증 구조

- 브라우저용 API는 `/api/auth/*`, `/api/admin/*`이며 Next.js가 내부 `/api/v1/*`로 전달합니다. 내부 서버는 기존처럼 루프백 또는 Docker 내부망에서만 제공합니다.
- 비밀번호는 salt가 포함된 BCrypt로 해시합니다. 8자 이상, UTF-8 기준 최대 72바이트입니다.
- 웹 세션은 256비트 임의 토큰으로 만들고 서버에는 SHA-256 해시만 저장합니다. 원문 토큰은 HttpOnly·SameSite=Lax 쿠키에만 저장하고 브라우저 응답 JSON·localStorage에 노출하지 않습니다. HTTPS에서는 Secure를 사용합니다. 세션은 7일 후 만료되고 계정당 최대 10개입니다.
- 인증된 게임·산책·PC 연결 관리 요청은 서버가 세션으로 강아지 소유자를 결정합니다. 브라우저가 보낸 세션·소유자 헤더는 전달하지 않습니다. 관리자 권한은 모든 관리자 API에서 검사합니다.
- 비밀번호 변경·재설정은 웹 세션과 PC 연결을 철회합니다. 재설정 링크는 30분, 이메일 인증 링크는 24시간 동안 한 번만 사용할 수 있습니다. 재발급 시 이전 링크를 무효화합니다.
- 회원 쓰기 요청은 같은 출처만 허용하고, 응답은 저장하지 않습니다. 인증·메일·가입 시도 횟수와 본문 크기를 제한합니다. 카카오 액세스 토큰·비밀번호·인증 링크를 로그에 남기지 않습니다.

## 검증

실제 회원·강아지 데이터와 분리된 메모리 DB에서 서비스 테스트를 수행합니다. 이메일은 외부로 전송하지 않는 로컬 SMTP fixture로, 카카오 사용자 정보는 서비스 테스트에서 모의 응답으로 확인합니다. 카카오 앱 및 실제 SMTP 운영 설정에 대한 연결 확인은 해당 설정을 준비한 뒤 진행합니다.

```powershell
cd backend
.\gradlew.bat test bootJar
cd ../frontend
npm run build
```

통합 검증 스크립트는 테스트 전용 3101 사이트와 격리 확인 변수 `PUPPY_TEST_ISOLATED=1`을 요구합니다. 관리자 테스트 데이터는 `@puppyruby.test`만 사용합니다.

2026-09-12 검증: 백엔드 58개 테스트와 격리 통합 검증 676개 항목을 통과했습니다. 실제 브라우저에서 가입, 별명 변경, 로그아웃·관리자 로그인, 회원 정지·해제, 공식 산책방 대화 조회와 320px 화면을 확인했습니다. 테스트 과정에서 외부로 이메일을 보내지 않았습니다.
